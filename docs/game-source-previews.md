# 発見候補の画像と紹介イベントの入口

## 今回の範囲

- Steam由来の候補に「ゲーム画面を見る」を追加。開いた時だけSteamの掲載スクリーンショットを最大3枚取得し、押すと元画像を開く。
- Wholesome Gamesの公式ページに掲載されたSteamリンクから、登録済みを除いた発売予定ゲームを最大3作品取得する編集室ページを追加。
- 概要はSteamの原文を表示し、ユーザーが気になる点を入力して既存の発見候補登録へ送る。AIを使わず、作品台帳への採用や記事公開もしない。
- 紹介元の名称・URLを候補の注目理由に残し、作品情報の出典はSteamとする。手動候補として記録する。

紹介元の編集方針はジャンルや雰囲気に偏り得る。公式サイトで紹介されている事実と、世間の人気・品質評価を混同しない。今回のページはイベント別の出展履歴や開催年を確定するものではなく、Wholesome Gamesの公式紹介ページを発見の入口に使う。

## 構成

- `lib/public-source-client.js`：サイズ・時間制限、リダイレクト禁止の公開情報取得。既存Steam研究と共用。
- `lib/steam-discovery-source.js`：既存の作品種別・App ID・発売予定検証を維持し、appdetails取得を画像/紹介元と共用。
- `game-source-utils.js`：ブラウザーとサーバーで共用するSteam URL・画像URL検証。
- `lib/game-source-previews.js`：Steam画像とWholesome Gamesのリンク解析。リンクを辿るのは固定Steam APIのみ。
- `lib/editor-source-previews-handler.js`：既存`/api/editor-games`の`resource=steam-media`と`resource=showcase`にGETのみ追加。既存の認証と機能フラグを共有する。
- `editor-game-media.js`：候補と紹介元ページ共用の画像表示。同じApp IDの取得はページ内で共用し、失敗時のみ再読込可能。
- `editor-showcase.html/js`：無料の紹介作品取得と既存登録APIへの接続。入力中の注目理由はsessionStorageに保存する。

サーバーレスAPI数は12件のまま。DB・RPC・既存の採用/保留処理は変更しない。写真は許可したSteam CDNの当該App IDの画像だけを表示する。任意URLの取得、画像プロキシ、動画の自動再生、AI画像評価は追加しない。

## 取得の上限と失敗時

- 公開情報の取得は8秒、HTML500,000bytes、JSON350,000bytesまで。リダイレクトは追わない。
- 紹介元の明示的なSteamリンクを先頭から最大12 ID解析し、既知IDを除いて最大6件の詳細を取得、発売予定ゲームを最大3件表示する。
- HTML形式が変わってリンクが読めない場合や紹介元取得失敗はエラー。個別作品の失敗は除外する。新規作品がない場合はその旨を表示する。
- 紹介元が認証・年齢確認・アクセス制限を要求した場合は停止し、回避しない。
- 画像は開いた時だけ取得。画像の失敗や未掲載は候補一覧と採用操作を妨げない。元画像/ストアを確認できる。
- 紹介作品の再取得で未登録の入力を破棄する場合は画面で確認。同じ候補の再登録は既存RPCの重複防止を利用する。

## 確認結果（2026-11-01）

有料AIなし・本番書き込みなしで、Wholesome Gamesから以下を取得できた。
- Milki Delivery：ミルキィの牛乳屋さん（Steam 4259360）
- Haunted Attractions Inc.（Steam 4717800）

Gimbap Heaven（Steam 4501140）の掲載スクリーンショットを3枚取得できた。
Day of the Devsの作品一覧は今回の取得がHTTP403だったため自動取り込み対象にはしていない。取得経路を変えて制限を回避する処理はない。

114件のNodeテストで既存機能の回帰、認証、入力検証、外部ホスト/別App ID/危険な画像URL拒否、重複リンク除外、既知作品の取得前除外、サイズ制限と取得失敗を確認。公開反映はユーザー確認後。

## 次の段階

1. スクリーンショットから遊びや見た目の特徴をAIで読み取る設計と少額検証（今回未実装）。画面の美しさを一律点数化して絵柄の多様性を潰さない。
2. 公式情報、世間の反応、AIの見立てを分けて保存・表示。反応には件数、期間、出典、実プレイ/発売前の期待の区別を付け、極端な少数意見を全体評価にしない。
3. 追加紹介元の取得可否・利用条件を調べ、同じ候補登録と画像表示を再利用する。
