# お気に入り作品の個別確認

作品管理の★は個別に新情報を確認する指定。自動公開の保証ではない。お気に入り以外の作品も通常収集の対象。手動の新規登録とタイトル検索からの登録はお気に入りON。AIの候補採用だけではONにしない。

管理リストから外すと `is_managed=false,is_favorite=false`。公開記事、作品、資料、カレンダーを削除しない。外した作品は表示フィルタから復帰できる。復帰だけではお気に入りONにしない。

## 既存収集役へ追加する実行指示

【お気に入り作品の個別確認：2026年11月5日ユーザー承認】
一般のニュース探索を維持したうえで、各実行で public.game_following の is_favorite=true AND is_managed=true の作品も確認する。お気に入りを自動公開や採点加点の根拠にしない。お気に入りOFF・管理対象外の作品も、通常の探索で見つかった新情報は従来通り扱う。AIが発見・登録しただけでお気に入りを勝手にONにしない。
接続確認後、games と game_following を game_id=id で結合し、game_sources のURLと出典種別、original_title、last_checked_at、check_outcome、check_note、updated_atを取得する。last_checked_at NULLS FIRST、game_idで安定ソートし、LIMIT/OFFSETで全対象を把握する。前回の実行枠に収まらなかった未確認作品を先にする。取得0件なら個別確認不要。接続・承認が必要なら停止し別経路で回避しない。
各作品の確認開始時刻はDBのclock_timestamp()で取得する。既存の公式サイト・公式ストア・公式発信元を確認し、必要なら作品名・原題で公式の新発表を検索する。メディア記事は発見の入口とし一次情報を開いて確認する。タイトル指定だけで登録された作品は、同名作品・機種・開発元を照合して作品の同定と公式出典の発見から始める。特定できない場合は推測で作品情報・発売日を確定しない。
公式出典を新たに特定し実際に確認できた場合だけ、当該game_idのgame_sourcesへ検証済みURL/source_type='official'又は'store'/review_status='verified'/observed_at/verified_atを保存してよい。同じgame_id+URLを先に確認し既存資料を上書きしない。この段落はお気に入り作品の新規資料保存を許可し、スキーマ・権限変更や既存記事変更を許可しない。
対象は新発表・発売日・公式動画・アップデート・DLC・客観的な人気拡大など従来の読者価値のある情報。既存の公式ページが存在することだけを新情報にしない。原則直近24時間。お気に入り個別確認に限り、前回の正常確認から24時間以上空いた場合は、その正常確認以降に発表された未収集情報も調べてよい（初回・前回失敗・一部確認の場合はまず直近24時間を確認し、期間が足りない場合はcheck_noteに残す）。発表日時・JST・対象地域と機種を確認し、一般記事と同じ重複除外と専用キューの保存・処理役への引継ぎを使う。未確認情報を推測して保存・公開しない。
候補保存直前にも対象のis_favorite/is_managed/updated_atを再確認する。解除・管理外し・確認開始後の設定変更があれば個別追跡としての保存を中止する。新規記事候補を保存したらarticle_gamesに当該作品との関連を重複なく追加してよい。通常のニュース探索として独立に採用した情報はお気に入り解除だけで除外しない。
実際に確認した作品だけ public.record_game_following_check(p_game_id,p_started_at,p_outcome,p_note,p_sources) で結果を保存する。p_started_atは当該作品の確認開始時に取得したDB時刻。p_outcomeは no_change（確認範囲で新情報なし）/news_found（新情報を確認）/partial（同定未完了・一部未取得・期間不足）/failed（確認できず）。p_noteは日本語2000字以内で確認範囲・新情報候補ID・未確認理由を記載。p_sourcesは実際に開いた出典URLと確認結果のJSON配列。SQLリテラルは安全にエスケープする。関数戻り値trueと再SELECTで保存を確認し、falseなら解除や新しい確認との競合として上書きしない。失敗を「新情報なし」にしない。未着手作品の確認時刻を更新しない。
終了時には個別確認した作品数、未確認件数と理由、新規保存IDを、一般探索と区別して簡潔に報告する。スケジュール、公開閾値、画像確認、処理役への引継ぎ、外部有料生成API禁止など他の保存済み指示は維持する。
