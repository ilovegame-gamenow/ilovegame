# メディアから話題を探す：最初の手動入口

編集方針は `game-editorial-experience.md` を正本とする。GAME Watchの公開RSS 1.0をボタン操作時に1回だけ読み、新しい話題を見つける入口を用意する。自動記事生成や、対象作品の自動抽出・採用ではない。

## 動作

- 情報源の設定一覧に一つだけ入口を表示。共通の編集室認証、日時表示、安全なDOM生成、公開情報の時間・サイズ制限付き取得を再利用する。
- 既存 `/api/editor-games?resource=media-preview` にGETのみ追加。API数は12のまま。カタログ・発見候補・新フラグ `MEDIA_DISCOVERY_ENABLED=true` がそろう時だけ利用可能。
- 固定RSSのみ取得。利用者指定URLは受け付けず、リダイレクト・再試行・定期取得は行わない。既存の8秒・500KB上限を適用。
- RSS先頭最大100項目を確認し、14日以内・未来日時でない項目を公開日時の降順に最大20件表示。リンクは同一ホストのnews/interview/preview/kikakuの記事に限定し、追跡クエリとフラグメントを落として重複排除。
- タイトル・記事公開日時・元記事リンク・こちらの確認日時のみ表示。本文・コメント・画像は取り込まない。DOCTYPE/ENTITYを拒否し、RSS 1.0の限定フィールドだけを読む。タイトルはテキストとして描画する。
- 全カテゴリの見出しなのでグッズ等も含まれる。画面にその範囲を明記し、自動で編集基準適合・人気・新作と認定しない。空なら「話題が存在しない」と断定しない。失敗時は前回結果を保持して確認時点を明記する。
- 元記事を開き、公式発表や元投稿で裏付けを取ってから、既存の発見候補フォームで作品名・概要・気になる点・公式の出典を登録する。今回は媒体見出しをフォームへ自動転記せず、登録UIを重複実装しない。

## 現段階の範囲

有料API・AI・DB書き込み・スキーマ変更なし。他媒体の接続、SNSのバズ判定、自動裏付け確認、発見元と公式出典の構造化保存は次段階。まとめサイト等の見出し・コメントをそのまま記事として再利用しない。

公開反映は所有者の確認後に新フラグを有効化して実施する。実際のRSSで、ユーザーが例示したプチプラネットの記事が含まれることを読み取り確認する。
