# メディアから話題を探す：最初の手動入口

編集方針は `game-editorial-experience.md` を正本とする。GAME Watchの公開RSS 1.0をボタン操作時に1回だけ読み、新しい話題を見つける入口を用意する。対象作品の自動抽出・採用ではない。選んだ見出しは未公開記事に登録して既存の編集欄を開ける。

## 動作

- 情報源の設定一覧に一つだけ入口を表示。共通の編集室認証、日時表示、安全なDOM生成、公開情報の時間・サイズ制限付き取得を再利用する。
- 既存 `/api/editor-games?resource=media-preview` にGETのみ追加。API数は12のまま。カタログ・発見候補・新フラグ `MEDIA_DISCOVERY_ENABLED=true` がそろう時だけ利用可能。
- 固定RSSのみ取得。利用者指定URLは受け付けず、リダイレクト・再試行・定期取得は行わない。既存の8秒・500KB上限を適用。
- RSS先頭最大100項目を確認し、14日以内・未来日時でない項目を公開日時の降順に最大20件表示。リンクは同一ホストのnews/interview/preview/kikakuの記事に限定し、追跡クエリとフラグメントを落として重複排除。
- タイトル・記事公開日時・元記事リンク・こちらの確認日時のみ表示。本文・コメント・画像は取り込まない。DOCTYPE/ENTITYを拒否し、RSS 1.0の限定フィールドだけを読む。タイトルはテキストとして描画する。
- 全カテゴリの見出しなのでグッズ等も含まれる。画面にその範囲を明記し、自動で編集基準適合・人気・新作と認定しない。空なら「話題が存在しない」と断定しない。失敗時は前回結果を保持して確認時点を明記する。
- 各見出しの「未公開の記事として登録・編集」で `/api/editor-save` の専用actionへ進む。サーバーが固定RSSを再取得し、その取得範囲にあるURLの見出し・公開日時を使って登録する。任意の本文やステータスは受け取らない。既存記事があればRSSを再取得せず開く。
- 新規記事は審査待ち・本文等は空・重要度0・自動AI処理対象外。出典URLの既存UNIQUE制約とignore-duplicatesで多重送信を処理し、既存記事・下書き・公開状態を変更しない。本文完成と人の掲載操作までは公開できない。
- 登録後は既存の記事編集フォームを自動で開く。戻る先は話題一覧。取得一覧は同一タブのsessionStorageに最大30分保持し、戻った際の再取得を不要にする。前回取得結果であることを表示する。
- 作品台帳への候補登録は引き続き既存の発見候補フォームを使用。記事登録と作品採用は別操作。

## 現段階の範囲

有料API・AI・スキーマ変更なし。選択した記事のみ既存articlesへ登録する。他媒体の接続、SNSのバズ判定、自動裏付け確認、発見元と公式出典の構造化保存は次段階。まとめサイト等の見出し・コメントをそのまま記事として再利用しない。

公開反映は所有者の確認後に新フラグを有効化して実施する。実際のRSSで、ユーザーが例示したプチプラネットの記事が含まれることを読み取り確認する。
