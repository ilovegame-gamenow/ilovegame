# Blueskyの公式資料プレビュー

## 今回の範囲

少量取得の調査と検証用コード（PR #24）を含み、編集室に読み取り専用プレビューを追加する。
`editor-social.html`でボタンを押した時だけ、公式サイトが案内するAmong Us StoryのBlueskyアカウントから最大5件を取得する。公開日時・確認日時・投稿へのいいね/再投稿/返信/引用数と、元投稿/公式案内元へのリンクを表示する。日時は共通GameDateで日本時間表示。

本文・プロフィールを保存せず、API応答の生本文も表示しない。原文は元投稿で確認する。DB保存・作品への紐づけ・記事作成・公開・AI処理・定期取得は今回追加しない。一般利用者の評判を収集した画面でもない。

## 共用と入口

- 既存`/api/editor-games?resource=bluesky-preview`へGETのみ追加。既存の編集室認証・作品機能フラグ・発見候補フラグを利用する。
- 新しい`BLUESKY_PREVIEW_ENABLED=true`が明示された時だけ取得可能。未設定なら準備中として停止する。
- 設定の情報源一覧のBluesky項目をそのまま使う。利用可能な場合だけ「作品の発見」に読み取りプレビューの入口を出し、追加候補と二重表示しない。設定画面は増やさない。
- 収集器は少量検証済みの`social-source-probe.js`を共用。ホスト/アカウント/上限は固定で、呼び出し側から変更できない。
- 新規APIエントリ・DB・設定保存先は追加しない。API数は12件のまま。

## 読み取り時の扱い

公式サイトからの案内でアカウントを確認し、API応答の投稿者・URI所有者も照合する。再投稿・返信・重複を除外する。欠けた統計は0ではなく取得不能と表示する。反応数を作品品質・購入意欲や世間全体の評価と呼ばない。

毎回1リクエスト、時間/サイズ制限あり。自動再試行しない。取得失敗時は前回結果の確認日時を残し、前回結果であることを明示する。画面の再読み込みだけでは外部APIを呼ばない。

## 検証と反映

123件のNodeテストで既存回帰、認証、GETのみ、入力拒否、フラグ、公開APIだけを1回呼ぶこと、DB書き込みなし、情報源の一意性を確認する。画面は模擬APIで検証し、未取得/取得結果/欠落統計/リンク/日本時間を確認する。

公開反映前に確認。承認後はコードの反映と本番のみBLUESKY_PREVIEW_ENABLEDを有効化し、5件以内の公開読み取りを確認する。有料APIやYouTube接続は今回行わない。
