# I LOVE GAME♪：読者が遊びを想像できる紹介へ

## 目指す読み心地

王道の新作をしっかり押さえながら、知らなかった作品にも出会える。見た目と遊びの面白さを一緒に伝える。知名度や「AIが選んだ」を魅力の代わりにしない。収集情報をそのまま並べるのでなく、読者が次に知りたいことへ案内する。

添付されたAI DISCOVERYの案は、画像→短い見出し→一言の魅力という読み順の参考にする。色は既存サイトのクリーム色・オレンジ・共通書体を軸に、余白と画像の大きさで整理する。管理画面の入力欄を読者向けカードへ流用しない。

## 当面の編集範囲（2026/11/02合意）

まずは次の形を完成させ、運用してから次の拡張を判断する。

| 柱 | 対象 | 記事化の条件 |
| --- | --- | --- |
| 新作・発売予定（中心） | 新作発表、発売日決定、新しい機種への展開、これから発売される作品 | 何が新しく発表されたかと公式の裏付けを確認 |
| ゲームの気になる話題（随時） | 驚くプレイ、独自の遊び方、ユーザー作品、開発の仕掛け・制作秘話、遊ぶ人に役立つ発見 | 元投稿・映像・発言の前後を確認し、面白さや有用性を具体的に説明できる |
| SNS・実況からの流行（十分な根拠がある時だけ） | 新旧を問わず、今になって注目が急増した作品 | 独立した複数の投稿・実況への広がりや一定期間の増加を確認。無理に記事数を確保しない |

発売済み作品を古さだけで除外しないが、新しい出来事のない過去作紹介は現在の収集の中心にしない。好みに合うかを確認するための参考作品と、今記事にする作品を混同しない。

「投稿ひとつが注目された」と「作品全体が人気になった」を別の判断にする。前者は興味深い投稿として紹介できても、後者の証拠にはしない。小さな兆しは内部候補で保留し、記事数を埋めるために「話題沸騰」「大人気」へ言い換えない。根拠がある場合も期間・媒体・確認できた反応の規模を示す。

### 発見から記事まで

1. メーカー公式、ゲーム専門メディア、まとめサイト、SNS・実況を発見の入口として使う。発見元URLと記事・投稿の公開日時を記録する。
2. 新作情報は公式発表・開発元・ストアへ、コミュニティの話題は元投稿・映像へたどる。複数サイトの同じ転載を独立した裏付けに数えない。
3. 作品は既存作品IDに集約し、機種別・地域別の発売予定は別に保持する。作品の初発表日、今回の発表日、記事公開日、こちらの確認日時を混同しない。「Switch 2版の発売前」を「全機種で未発売」と扱わない。
4. 編集室に候補と根拠を置き、掲載する理由・保留理由を確認する。発見しただけで記事や作品を自動公開しない。
5. 画像・映像と具体的な遊びが伝わる紹介を作る。元記事の見出し・本文・コメント集の転載で紹介を作らない。

GAME Watch、ファミ通、4Gamer、電ファミなどのゲーム専門メディアを発見の参考にする。オレ的ゲーム速報＠刃、はちま起稿も話題発見の参考として使えるが、見出しや選ばれたコメントを事実確認の代わりにしない。いずれも自動接続済みという意味ではなく、収集方法・設定は既存の情報源一覧に集約して段階的に実装する。

個人への晒し・攻撃、機種対立を煽ることが中心の話題、未確認リーク、発言の切り取りは当面の掲載対象にしない。不具合・サービス終了・利用上の注意は、煽りの強さではなく遊ぶ人への具体的な影響と確認できた事実で判断する。

この合意は編集方針であり、自動収集やAI評価に実装済みという意味ではない。SNS横断検索・自動バズ判定を先に増設せず、まず手動の発見・根拠確認・編集室での選択から記事までを整える。

## 公開内容の役割

| 表現 | 読者に伝えること | 中心のデータ |
| --- | --- | --- |
| ニュース | 今回、何が発表・変更されたか | 記事＋対象作品 |
| 発見・作品紹介 | 何をするゲームで、どこが楽しそうか | 作品＋画像・映像＋編集コメント |
| 発売カレンダー | いつ、どの機種で遊べるか | 作品＋機種/地域別の発売情報 |
| 作品の詳細 | 遊び・対応機種・発売日・関連情報をまとめて知る | 同一作品の情報を集約 |

同じ作品の機種別発表を別作品として増やさない。作品を中心に、対応機種/発売情報/ストアを紐づけ、記事はその作品の新しい出来事として関連づける。リメイク、リマスター、移植、DLCは版の関係を確認し、タイトル一致だけで自動統合しない。

## 発見カードの具体案

1. 横長のゲーム画像。ロゴより、遊びや世界観が分かる画面を優先する。必要に応じて画像を切り替えられるようにする。
2. 作品名と、遊びが伝わる短い見出し。「まだ知られていない名作」「海外で話題」のような未確認の評価を置かない。
3. 何をして、どう楽しいのかを1〜2文で説明する。管理/探索/協力といった単語だけで終えず、プレイヤーの行動を書く。
4. 確認できた機種・発売予定・体験版の有無。未確認の項目は付け足さず、日付が曖昧ならその精度のまま表示する。
5. 「どんな遊び？」から共通の作品詳細へ進む。

例（説明文で確認できた範囲、公開前の文案）：

- **Milki Delivery：ミルキィの牛乳屋さん**
- 見出し案：**牛乳を届けながら、村の暮らしに触れる小さな冒険**
- 紹介案：自転車の配達サービスを営む少女と、片田舎へ。牛乳を届けたり、相棒の牛の食べ物を集めたりしながら、村の人々と出会います。

「どこが面白そう？」という編集コメントは、確認できた機能説明と分ける。未体験であるのに、実際に遊んだような評価を書かない。

## 世間の声の扱い

公式情報・世間の反応・AI/編集者の見立てを分ける。反応には出典、取得期間、件数、実プレイ/発売前の期待を付ける。肯定/否定の強い言葉を代表意見として抜き出さず、複数の具体的な指摘と、その前提を確認する。反応がない作品を低品質と扱わない。

Among Us、スプラトゥーン、マリオのように、駆け引き・独自アクション・触って試したくなる仕掛けを発見時の参考にする。ただし主要作品を広く集める段階で好みによる除外をしない。かわいい/暗いなどの絵柄だけで採否を固定せず、意外な発見の枠を残す。

## 段階

1. 今回：設定と情報源を一元化し、管理の重複を防ぐ。公開ページは変更しない。
2. 次：実データの作品を使い、発見カードと共通作品詳細のプレビューを作る。画像・見出し・余白を確認してから公開方法を決める。
3. 作品の機種/発売情報と記事の関連を整え、カレンダーや注目作品へ再利用する。
4. 世間の反応を別データとして追加し、出典・件数・時期を確認できる形にする。

公開反映や追加の有料AI実行は、具体的な変更内容・費用を示して確認後に行う。
