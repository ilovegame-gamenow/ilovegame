# 情報源と収集設定を1か所へ

## 管理の置き場所

| 役割 | 唯一の管理場所 |
| --- | --- |
| 情報源の対応状況・リンク・収集件数 | 編集室の設定 → 情報源と収集 |
| 記事の表示件数・掲載しきい値 | 同じ設定ページ → 表示・掲載 |
| AI評価の編集方針 | 同じ設定ページ → AIの編集方針 |
| 記事の確認・編集・掲載判断 | 記事一覧・編集画面 |
| ゲームを探す・候補を採用/保留する | 作品発見と候補の作業画面 |

別の情報源設定ページを増やさない。編集室の設定を1つの保存フォームとして維持し、ページ内リンクで目的の項目へ移動する。作業画面のリンクはこの設定へ戻す。収集する最大件数と、読者向けに表示する件数は役割が違うので混ぜない。

## 実装

- Nintendo/PlayStationの表示用メタデータを既存`newsSources`に追加。収集可否・件数キーは実行側と共用する。
- `getInformationSources`が既存の収集設定と機能フラグから状態を作り、既存`/api/editor-settings`の応答へ追加する。新API・新DB・新しい設定保存先なし。
- 収集件数の入力は、APIが返す情報源と共通の設定ルールから作る。2か所に同じ入力を残さない。APIの既存バリデーション、認証、同一オリジン、単一設定レコードへの保存を維持する。
- 作品発見はSteamとWholesome Games。既存機能フラグが閉じている時は準備中/画像確認のみとし、実行できない操作リンクを表示しない。
- 追加候補はXbox、カプコン、スクウェア・エニックス、バンダイナムコ、itch.io、Day of the Devs。収集器も入力欄も追加せず、候補であることを明記する。
- 情報源の状態は保存済み設定に基づく。0件で停止とし、保存前の変更で稼働状態を断定しない。
- このリポジトリの収集ワークフローはworkflow_dispatch。収集対象という状態から「定期実行中」「取得成功」と推測しない。収集の実行履歴はまだこの画面で記録していないことを明記する。

今回、収集・AI・公開のルールや保存済み設定値を変更しない。候補/記事を作成しない。DBマイグレーションも不要。公開反映はユーザー確認後。

## 確認

117件のNodeテストで既存設定保存と既存機能の回帰、0件/収集器無効による停止、機能フラグとの整合、追加候補が設定や収集対象に混ざらないこと、設定欄の重複なし、秘密情報を返さないことを確認。

今後、実行日時・取得件数・成功/失敗を記録する場合は、ニュースと作品発見それぞれの実行結果を実行単位で保存し、情報源IDでこの一覧へ接続する。記事の作成日時を収集成功日時として代用しない。
