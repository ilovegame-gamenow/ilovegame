# Steam手動リサーチ：最小のAI発見経路

## 範囲

Steamの公開ストア情報から近日登場作品を読み取り、既存候補・作品の出典URLに対応するSteam App IDを除外して最大3作品を準備する。
AIは取得済みの説明文から作品概要と面白そうな点を整理する。ウェブを自由に巡回するエージェントや人気判定ではない。
まだAIによる実データの品質評価は行っていない。まず少数の手動実行で評価する。

情報源はSteamだけ。定期実行、記事の自動作成、作品への自動採用、発売日の自動登録は追加しない。
Steam `featuredcategories` のcoming_soonと各appdetailsを使用する。公開ストア由来の非保証エンドポイントなので、形式変更・取得拒否・取得失敗時は止める。認証壁・年齢確認・アクセス制限を迂回しない。

## 手動の流れ

1. 「対象作品を取得」で最大3作品の出典・説明文を保存する。AI呼び出しは行わない。
2. 対象と概算費用を確認し、「AIで候補を作成」を明示的に実行する。
3. GPTが返した根拠の引用が、保存した原文の中に存在するか検証する。
4. 対象App IDが一致する結果だけを、候補と調査結果をまとめたトランザクションで保存する。
5. 既存の発見候補画面で、人が保留・採用する。

作品名・URLはAIに生成させず、Steamから取得した値を保存する。新しい候補だけをdiscovered_by=aiとし、元の候補や手動の確認状態を上書きしない。

## 課金と実行制御

- 既存記事パイプラインと同じ `gpt-5-mini` を使用する。このPRで既存モデルを移行しない。
- Responses APIを1回だけ実行。toolsは渡さず、入力JSON全体は25,000 UTF-8 bytes以内、出力は3,000トークンまで。
- 2026-11-01に公式モデルページで確認した標準価格：入力$0.25／100万トークン、出力$2.00／100万トークン。
- UIには1回$0.02以下という保守的な概算を表示する。請求額を固定するものではなく、価格改定やアカウント条件は別途確認する。実行結果にはAPIのusageを保存する。円換算は固定しない。
- API POSTにはconfirm_cost=trueが必須。初期状態ではGAME_RESEARCH_ENABLED未設定で無効。
- 調査をDBでclaimしてからAIを呼ぶ。同じ調査の二重実行・並行実行を防ぎ、JSTで1日最大3回に制限する。失敗した実行も回数に含める。
- 準備の有効期限は30分。同じ調査を実行可能な状態へ戻す処理はない。
- 外部APIのエラー・不完全応答・出典と一致しない根拠・保存失敗では、自動再試行しない。使用量が分からない失敗では課金済みの可能性を否定しない。
- プロセス中断でrunningが残った場合、同じIDを再実行しない。10分以上続く場合は状態とログを管理者が確認する。別の調査にも同じ日次上限を適用する。

現在の公式モデルページはgpt-5-miniにDeprecatedの表示がある。使用中モデルの実利用可否は、承認された少額の実API検証で確認する。新モデルへの移行は、費用・品質を別途比較して扱う。

## データと権限

追加テーブルは `game_research_runs`。出典スナップショット、処理状態、実行日時、結果、usage、モデル、プロンプト版を保持する。
新テーブル・RPCはサーバー専用。RLS有効、PUBLIC/anon/authenticatedの権限なし、SECURITY INVOKER、search_path空。
AI候補の完了保存と候補登録は1トランザクション。保存途中の失敗では候補だけが残らない。
既存のAPIへresource=researchでルーティングし、認証・同一オリジン確認を共用する。API数は増やさない。
既存の記事生成・評価も含めResponses本文抽出を共通化するが、既存のプロンプトや掲載判断は変更しない。

## 承認と反映

コード・SQL・模擬AI応答のテストは先に実施する。本番反映と有料APIの実行はユーザー確認後。
承認後に `database/game-research.sql` を適用し、本番だけGAME_RESEARCH_ENABLED=trueを設定してコードを反映する。
実データのAI試行前には対象最大3件、モデル、概算$0.02、外部API送信の対象が公開Steam説明文であることを確認する。
Vercelの既存OPENAI_API_KEYをサーバーから使用し、ブラウザーへ渡さない。
既存記事の収集スケジュールを変更しない。

## 検証

- Nodeテスト：Steamの形式・ゲーム種別・発売予定・App ID照合、既知作品の除外、AI入力上限と根拠検証、認証・費用確認・フラグ、無料準備、有料経路の1回claim、失敗時の再試行禁止。
- 隔離DB：スナップショットの保持、同時claim、日次上限、根拠不一致の拒否、AI候補と結果の原子性、手動候補の維持、公開ロールの拒否。
- 実PostgREST：本物のDB・HTTPで準備・排他claim・候補保存を確認。AI結果は固定の検証データで、有料APIは呼ばない。
- `node tests/live/steam-discovery-source.mjs` は公開Steamの読み取りだけ。DB書き込み・AI呼び出しなし。
