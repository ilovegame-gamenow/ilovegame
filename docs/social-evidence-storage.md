# SNS資料と作品の関連づけ

Blueskyの公式投稿を読み取り、編集者が既存作品を検索して対応を確認し、投稿単位で保存する。作品・記事の自動作成や公開、AI評価は行わない。

## 保存構造

既存の `game_sources` の `(game_id,url)` を再利用する。出典の審査状態は変更せず、新規出典は確認待ち。反応数は `game_social_observations` に確認日時・公開日時・公式アカウントの案内元とともに分けて保存する。欠落値はnull、0は0。投稿本文・プロフィールは保存しない。

同じ取得結果を再送しても複合主キーで増殖しない。後日取り直した数値は過去の記録を上書きしない。同じ投稿を複数作品に関連づける場合も作品ごとの資料として扱い、機種ごとに作品を複製しない。

## API・アクセス

既存の `/api/editor-games?resource=social-evidence` にGET/POSTを追加。認証・POST同一オリジン検証は親APIを使用。保存にはサーバーが署名した1時間以内の取得結果と、その中の投稿URLを必要とする。任意の反応数や投稿URLを送って保存することはできない。保存時にSNSを再取得せず、画面で確認した時点の記録を保存する。

保存先は選択した既存作品のみ。DBの外部キーと単一RPCで出典・観測を原子的に保存。テーブルはRLS有効、anon/authenticatedには権限なし、service_roleのみ読み書き。読取は作品単位で最大100出典・各直近20観測。現段階では紐づけ解除・資料削除のUIは未提供。

## 反映手順

1. PRのNodeテストと隔離PostgreSQL/REST CIを確認。
2. 所有者の公開反映承認後に `database/game-social-evidence.sql` を適用。
3. `SOCIAL_EVIDENCE_ENABLED=true` を本番環境に設定し、PRを反映。
4. 編集室の作品検索・取得・保存済み資料表示を確認。実データへの保存は対象作品を人が確認してから行う。

有料API呼出しなし。YouTube/X/Threads/TikTokの接続、評価指標、自動収集はこの変更に含まない。
