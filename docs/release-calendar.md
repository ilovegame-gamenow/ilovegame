# 発売日カレンダー：最初の段階

2026-11-03時点で本番作品1件（下書き）、発売情報0件。今回の変更は読み取り専用で、本番データ・スキーマ・権限・収集タスクを変更しない。公開反映前に確認する。

## 画面とデータ

`/calendar.html` に月別カレンダーと発売日順の作品カードを置く。機種で絞り込み、同じ作品・日付・発売形態・地域の機種をまとめる。早期アクセス開始は正式発売と分ける。月までの予定は日付確定のカレンダーに混ぜず、別欄に置く。年のみ・発売日未定・延期・中止は今回の月別表示に含めない。

日本と全世界の発表は別の選択肢にし、全世界から日本発売や日本語対応を推測しない。作品画像の保存先は現在の作品DBにはないため、最初の段階では見出しと日付・機種を中心にする。

`/calendar.html?demo=1` は表示確認専用。架空のサンプルと明記し、DBには接続・保存しない。通常の画面でサンプルへ自動切り替えない。データ0件、読込失敗、確認済みの発売情報がある場合を区別する。

## 既存機能の共用と公開条件

既存の12個のAPI関数を増やさず、`/api/news?resource=calendar&month=2026-11` に読み取りを追加。既存ニュースの一覧・詳細は従来どおり。catalogRequestでサーバーから既存のgames/game_releases/game_sources/game_platformsを取得する。秘密鍵をブラウザーへ返さず、公開列を明示的に組み立てる。RLSや匿名権限を広げない。

公開条件は作品published、発売情報verified_atあり、出典verifiedかつverified_atあり、officialまたはstore、発売状態announcedまたはreleased。DBの結合フィルターと出力前の条件確認の両方で適用する。出典が取り消されたら次回読み込みで表示から外れる。最大2000行までを500行ずつ読み、超過を検知したら絞り込みを案内する。総件数を網羅したと断言しない。

発売日はDATEとして比較し、時差で日付をずらさない。初期月と「今月」は日本時間。日付・結合の共通処理はrelease-calendar-model.jsに置く。

## 次の段階

発売日の登録を別の管理ページに増やさず、作品管理の作品に紐づける。公式出典と照合した発売情報を登録し、ニュース収集から見つかった日付はその候補として扱う。記事の重要度・自動掲載と、発売日の事実確認・作品公開は別の判断を維持する。

現スキーマは同一機種・地域・正式／早期アクセスにつき発売情報1件であり、パッケージ版とダウンロード版の別日発売を十分に表せない。これらが異なる場合は無理に1日にまとめて登録しない。版の区別は次のデータ設計で扱う。ニュース本文の推測や自動抽出をそのままカレンダーの確定日にしない。

## 検証

Nodeテストで公開条件・日付範囲・不正入力・機種統合・月予定の分離・件数超過・既存APIへの影響を検証。既存の隔離PostgREST統合テストにも、実際の結合と出典却下時の非表示を追加。ブラウザーで日付選択・月移動・機種絞り込み・空表示・失敗と再試行・モバイル幅を確認する。本番の保存操作は行わない。
